## Within-chunk dedupe candidates

- **XP-to-level curve (triangular / log / polynomial)** → engine path `createSkill` — appears in (Looper #1, Looper #2, Looper #13, Scripter #3). All use `xpToLevel` SkillCurve factory with different formula shapes; wiring is identical.

- **Modifier-product on action/yield rate** → engine path `createModifierChain` + `createMultiplicativeModifier` — appears in (Looper #3, Scripter #1, Explorer #2, Packer #1, Packer #2, Packer #8, Cycler #1, Cycler #5). The modifier-chain composition pattern for rate scaling is the single most-shared engine path in this chunk.

- **Geometric cost scaling** → engine path `createScalingPurchasable` — appears in (Scripter #5, Packer #10, Cycler #2). All are §2.4 geometric ladders; wiring is `createScalingPurchasable({ baseCost, costScaling })`.

- **Piecewise binary unlock threshold** → engine path `booleanRequirement` + `'notNow'/'never'` `canRun` — appears in (Looper #12, Explorer #6, Explorer #7, Cycler #9). All are §2.9 regime gates on a single threshold crossing.

- **Stochastic load-bearing: weighted item draw** → substrate `weightedPick` — appears in (Scripter #8 via `chance()`, Explorer #8, Packer #7). All route through `weightedPick` or `chance()` from primitives; distribution-shape probing goes to `runSensitivity`.

- **Combinatorial selection: spatial arrangement** → substrate `createSpatialGrid` + `runMatrix` — appears in (Explorer #10, Packer #3, Packer #9). All are "per fixed assignment closes; across assignments combinatorial." Substrate wiring is identical.

- **Optimal stopping: reset timing** → substrate `runMatrix` over reset-threshold strategies — appears in (Looper #18, Scripter #9, Cycler #12). All are Bellman-policy decisions; simulation substrate is the engine's answer.

- **Network-topological path / allocation** → substrate `createSpatialGraph` — appears in (Scripter #10, Explorer #9, Cycler #10). All route through `SpatialGraph` for topology; consumer-side algorithm for the routing or allocation problem.

- **Prestige currency via sub-linear formula** → engine path `createCumulativeConversion` — appears in (Packer #12, Cycler #12). Both use a sub-linear exponent on run score; `createCumulativeConversion` + `createPolynomialFormula` is the wiring.

- **Phase-scoped modifier gating** → engine path `createMultiplicativeModifier` with `enabled` callback — appears in (Cycler #1, Cycler #3, Cycler #8). The `Grant.when` / `enabled` gate pattern is the OL-568-verified mechanism for phase-specific modifier activation.

## Falsification log

**Explorer #3 (fog reveal) — partial verdict.**
Read `createContentRegistry` (src/systems/content-registry.ts), `createZoneSystem` (src/systems/zone.ts), and `computeVisibility` (src/core/feature.ts). `ZoneSystem` tracks unlocked/current zones but has no per-sector visibility-state primitive. `createContentRegistry` stores content defs per zone but does not track per-instance `fogged | glimpsed | explored | scouted` state. `computeVisibility` operates on `Visibility` enum for feature display, not for sector fog-of-war. `createSpatialGrid` stores cell occupancy but no per-cell fog state. Explorer archetype doc §3 stress axis 4 explicitly names "Fog-of-war visibility state" as a consumer-wired gap with the question "does the engine need a `VisibilitySystem` primitive?" No entry in `candidate-primitives.md` yet. Verdict: partial — the engine provides the persistence substrate (`persistent` per-sector refs) and the zone system, but not a first-class fog-state tracker. Gap is real but pre-threshold (no candidate entry filed; no N=2 consumer).

**Packer #4 (combine-up) — partial verdict.**

## Open questions for synthesis

1. **Looper #15 (queue-as-plan) and Scripter #11 (script optimization) both use `createSequencer` as substrate but for categorically different purposes.** Looper uses `mode: 'list'` for a drag-edited persistent plan; Scripter uses `createSequencer` for tier-1 linear script execution. These share the primitive but not the usage pattern. Synthesis should call out that "Scripter tier-2+ forks replace the sequencer with a custom interpreter" (Scripter §3 stress axis 1 — `createScriptRuntime` is the named gap). The two archetypes should not be conflated in the cross-chunk dedup just because they both touch `createSequencer`.

2. **Packer #3 (spatial arrangement) and Explorer #10 (loadout) and Scripter #11 (script optimization) all n/a to combinatorial-selection substrate.** Do they share a harness citation pattern? Packer uses `createSpatialGrid` + `runMatrix` over arrangement perturbations; Explorer uses `createInventory` + `createSlot` for the bag/slot state; Scripter uses `createContentRegistry` + `walkContent` for command enumeration. The substrate varies by archetype even though the bifurcation bucket is the same. Synthesis should document the three distinct substrates rather than collapsing them to a single combinatorial-selection path.

3. **The `Grant.when` / `enabled` modifier-gate pattern** (Cycler #1, #3, #8) is the OL-568-verified path for phase-scoped modifiers, but `createPhaseMachine` is parked in `candidate-primitives.md` as an ergonomics candidate. At what `Grant.when` surface area does the ergonomics gap materialize? Cycler stress axis 1 says "2–4× the `Grant.when` surface area of a single-mode archetype." The first Cycler fork is what confirms whether this stays ergonomic. Synthesis should flag this as the highest-urgency ergonomics-watch item in this chunk — it's one fork away from a graduation trigger.

4. **Network-topological substrate citation consistency.** Scripter #10 (RAM allocation over server graph), Explorer #9 (path planning over sector adjacency), and Cycler #10 (dig-path topology) all n/a to `createSpatialGraph`. But Scripter's server network is a directed node-capacity graph, Explorer's sector adjacency is an undirected stamina-weighted graph, and Cycler's tunnel network is a player-carved grid. Do all three resolve cleanly to `createSpatialGraph`, or does Scripter's directed RAM-allocation shape need `SpatialGraphOptions.directed: true` or a separate `createSpatialGraph` configuration? The synthesis pass should check whether `SpatialGraph` covers directed weighted graphs or is undirected-only.

5. **Looper #16 (PK2 fractional retention) and the `createRetentionPolicy` `retain: Map<Persistent, transform>` API** is the n=1 consumer of `fractional()` in this chunk. The Explorer archetype (persistent-progression, no reset) never touches `createRetentionPolicy`. Cycler's cross-cycle state uses `persistent` directly. The `createRetentionPolicy` primitive is almost exclusively Looper-territory in this chunk. If the Scripter archetype ever adds prestige (Bitburner Source Files shape), it would be the second `createRetentionPolicy` consumer. Synthesis should track this as a primitive-utilization note: `createRetentionPolicy` is load-bearing for Looper but dormant for the other four archetypes.
